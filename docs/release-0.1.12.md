# CoSkin 0.1.12

One CoSkin resident manages supported Codex windows through one authenticated connection. Connection and simultaneous motion limits are separate: five connections and two playing windows by default, configurable from one to ten with playback no higher than connections. Focus and visibility decide which windows play; unsaved edits, previews, and pending requests preserve their connection. A closing or slow window retries independently, while a closed shared transport triggers connection recovery.

After a theme has been saved or imported, a failed notification to a closing window no longer turns the completed operation into a failure response. Requests receive their result before notifications to the other windows, and each notification has a two-second deadline. If the theme library cannot open after import, the import succeeds with its interface deferred. Window identity and the failed initialization step are recorded without chat contents or authentication secrets.

Completed replies remain associated with their original window and request until acknowledged. Requests arriving while an earlier reply is being acknowledged are drained within the same bounded delivery pass, preventing the startup sequence from waiting for its own recovery loop. Transport calls share a total time budget for lock acquisition and response handling. An in-progress framed pipe write retains its lifetime cancellation rather than leaving a partially written frame.

Theme cards and details distinguish images, animated images, and videos, with video duration read from the actual background container. Covers and personal icons do not determine the background type. Small cached metadata reads use a two-request queue and the existing preview visibility observer; the one-line list does not start preview or metadata loads. Previous and next buttons follow the current folder, filters, and sorting across page boundaries without applying the theme. Draft changes require save, discard, or continued editing before navigation.

Start-screen greetings and their decorative icons are hidden by default, including project-name prompts. Users can restore them in settings; actual messages, input controls, and menus remain intact. Background-only view reuses the current player and hides the foreground below the native titlebar. Toggle again or press Escape to restore focus, scrolling, and interface state. Its button participates in the existing horizontal titlebar flow, with a CoSkin menu and Alt+Shift+B fallback when the titlebar or free space cannot be identified.

Background detection recognizes common shell markers, semantic main regions, and large structural wrappers for new screens rather than relying on route names alone. Messages, editors, smaller functional panels, computer previews, and embedded content retain their native paint. This does not guarantee support for an unknown future layout. Hidden retained screens are excluded from composer and titlebar selection, and a refresh while motion is paused preserves the existing decoration.

The reported intermittent .NET dialog has not been reproduced. These changes address observed source and startup failure paths and controlled two-window transport tests; they do not establish the cause of that earlier dialog. Separate local QA clients record handled failures and return a nonzero exit code instead of allowing an unhandled .NET exception. Actual replay validation and its window-count limits are recorded in the support matrix; a configurable maximum is not a measured ten-video performance guarantee.

Existing themes, media, preferences, and Codex processes are preserved.
