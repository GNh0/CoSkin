# .coskin 파일 형식 v1 초안

작성일: 2026-09-26 · 설계 상태: 초안 · 제품 문서: [CoSkin 설계서](CoSkin-설계서.md)

이 문서는 **테마스킨 목록으로 스킨을 가져오고 공유용으로 내보내는 교환 형식**의 계약과 구현 기준을 정한다. 실제 적용은 내부 목록과 hash 자산을 사용한다. 파일 입력·내보내기·재가져오기·외부 원본 삭제 후 적용은 검수 복사본에서 확인했다. 최대 크기·모든 비표준 ZIP·충돌 선택까지 검증된 것은 아니다. 정확한 경계는 [구현 상태](support-matrix.md)와 독립 검수에 기록한다. 첫 테스트 배포의 범위와 제한은 [0.1.0-beta.1 안내](release-0.1.0-beta.1.md)를 확인한다.

## 1. 컨테이너

- 확장자: `.coskin`
- 사용자에게 보이는 유형: CoSkin 테마
- 내부 구조: ZIP, UTF-8 JSON과 패키지 내부 이미지
- 형식 식별자: `coskin.theme`
- 형식 버전: 정수 `1`
- 압축: Store 또는 Deflate. 암호화·분할 ZIP·중첩 압축·실행 파일은 v1에서 허용하지 않는다.

파일명은 한글 등을 사용할 수 있다. 패키지 내부 경로는 아래의 제한된 상대 경로를 쓴다. 확장자만 바꾼 임의의 ZIP이나 다른 형식 파일은 CoSkin 테마로 받아들이지 않는다.

```text
Aurora.coskin
  manifest.json
  theme.json
  assets/
    search.png
    background.webp       선택 사항
  preview/
    cover.png             선택 사항
```

실제 예제는 [manifest.json](examples/manifest.json), [theme.json](examples/theme.json), [검색 버튼 이미지](examples/assets/search.png)에 둔다. 예제는 선택·호버 배경과 검색 버튼 이미지를 보여 주는 최소 데이터다. ZIP 파일이나 실행 가능한 완성 테마 제품은 제공하지 않는다.

## 2. manifest.json

| 필드                    | 형식·의미                                                  |
| ----------------------- | ---------------------------------------------------------- |
| `format`                | 반드시 `coskin.theme`                                      |
| `formatVersion`         | 반드시 정수 1                                              |
| `id`                    | 테마의 안정적 ID. 새 복제본은 새 ID 사용                   |
| `name`                  | 화면에 표시할 테마 이름                                    |
| `version`               | 콘텐츠 버전. SemVer의 major.minor.patch 사용               |
| `description`           | 선택적 설명                                                |
| `author.name`           | 제작자가 입력한 표시 이름. 인증된 제작자임을 보장하지 않음 |
| `engine.minVersion`     | 필요한 CoSkin 엔진의 최소 버전                             |
| `requirements.required` | 반드시 지원해야 하는 대상·효과 기능 ID                     |
| `requirements.optional` | 지원되지 않아도 생략 가능한 효과·대상 기능 ID              |
| `entry`                 | v1에서는 `theme.json`                                      |
| `defaultProfile`        | 처음 선택할 프로필 ID                                      |
| `preview`               | 선택적 미리보기 파일 상대 경로                             |
| `files`                 | manifest 자신을 제외한 모든 파일의 path, bytes, sha256     |

`id`는 소문자 영문·숫자와 점·하이픈·밑줄로 된 1~128자 식별자다. 개인 제작 시 생성한 UUID도 쓸 수 있다. 갤러리의 소유권은 업로더 계정과 별도 서명·카탈로그 정보로 관리하며, ID에 유명 제작자의 이름을 넣었다고 그 제작자가 되는 것은 아니다.

`files[].sha256`은 압축 전 원본 파일 바이트의 SHA-256을 소문자 64자리 16진수로 적는다. ZIP 메타데이터나 압축 결과를 해시하지 않는다. manifest 자신을 목록에서 제외하여 자기 참조를 피한다.

해시 일치는 파일 손상을 확인하는 수단이며, 제작자 인증이나 신뢰성을 보장하지 않는다. 카탈로그는 다운로드한 전체 패키지의 해시도 별도로 제공할 수 있다.

## 3. theme.json과 프로필

루트에는 `profiles` 배열을 둔다. 각 프로필은 `id`, `name`, `rules` 배열로 구성한다. manifest의 기본 프로필은 실제 배열에 존재해야 한다.

한 패키지에 어두운 배경, 밝은 배경, 정적인 외형처럼 여러 프로필을 넣을 수 있다. 프로필은 프로젝트 이름이나 실제 채팅 ID에 종속되지 않는다. 어느 프로젝트·채팅에 쓸지는 가져온 PC에서 연결한다.

규칙 구조는 다음과 같다.

```json
{
  "id": "thread-row",
  "target": "sidebar.thread-row",
  "states": {
    "base": {
      "style": {
        "background": { "color": "#ffffff", "opacity": 0.04 }
      },
      "motion": { "mode": "none" }
    },
    "selected": {
      "style": {
        "background": { "color": "#6d9eff", "opacity": 0.2 }
      }
    },
    "hover": {
      "style": {
        "background": { "color": "#ffffff", "opacity": 0.12 }
      },
      "motion": {
        "mode": "effects",
        "events": {
          "enter": [
            {
              "id": "reveal-hover",
              "layer": "background",
              "effect": "reveal.edge",
              "effectVersion": 1,
              "durationMs": 220,
              "delayMs": 0,
              "easing": "ease-out",
              "iterations": 1,
              "reverse": false,
              "parameters": { "direction": "left-to-right" }
            }
          ],
          "exit": [
            {
              "id": "close-hover",
              "layer": "background",
              "effect": "reveal.edge",
              "effectVersion": 1,
              "durationMs": 160,
              "delayMs": 0,
              "easing": "ease-out",
              "iterations": 1,
              "reverse": true,
              "parameters": { "direction": "left-to-right" }
            }
          ]
        }
      }
    },
    "selectedHover": {
      "style": {
        "background": { "color": "#6d9eff", "opacity": 0.3 }
      }
    }
  }
}
```

규칙 ID는 같은 프로필 안에서 고유해야 한다.

## 4. 대상과 범위

`target`은 CoSkin이 정의한 논리 ID다. 예: `navigation.search`, `sidebar.project-row`, `sidebar.thread-row`, `sidebar.thread-preview`, `surface.main`, `composer.surface`.

하나의 프로필 안에서 같은 target을 두 번 정의하지 않는다. 동일 대상에 여러 효과를 주려면 한 규칙 안에서 레이어와 효과 목록을 조합한다. 개별 버튼은 각기 다른 target ID를 사용한다.

원시 CSS 선택자, JavaScript 표현식, 번역된 버튼 이름, 임의 HTML, Codex 내부 클래스명은 규칙에 넣지 않는다. 내보내기에서 임시로 선택한 DOM 노드를 그대로 저장하지 않는다.

실제 프로젝트·채팅·특정 항목에 대한 연결은 로컬 `bindings.json`이 담당한다. 내보내기 시 사용 중인 특정 범위의 외형을 공유하려면 해당 범위를 계산하여 일반 프로필로 변환한다. 다른 사람의 PC에 존재하지 않는 프로젝트를 자동 생성하지 않는다.

필수 target의 지원 여부는 현재 창에 그 요소가 보이는지와 구분한다. 예를 들어 메뉴가 닫혀 있어 버튼이 안 보이는 것은 미지원이 아니다. 어댑터에 해당 종류를 찾고 꾸미는 기능 자체가 있는지를 검사한다.

## 5. 상태와 스타일 병합

상태 키는 `base`, `selected`, `hover`, `selectedHover`, `focusVisible`, `pressed`, `disabled`다. 범위를 먼저 합성한 뒤 활성 상태를 이 순서로 합성한다. `selectedHover`는 선택과 호버가 모두 참일 때만 활성화된다.

스타일은 알려진 객체 속성을 재귀적으로 합성한다. 배열은 통째로 교체한다. 효과 목록은 상위 목록에 자동으로 덧붙이지 않는다.

| 값                       | 의미                                                  |
| ------------------------ | ----------------------------------------------------- |
| 속성 생략                | 상위 범위·기본 상태 값을 상속                         |
| 속성의 `null`            | 해당 CoSkin 덮어쓰기를 제거하여 원래 앱 외형을 사용   |
| 배경 `opacity: 0`        | 어댑터가 관리하는 해당 배경 표면을 완전 투명하게 표시 |
| `motion.mode: "none"`    | 상속된 효과까지 끄고 최종 정적 외형 표시              |
| `motion.mode: "effects"` | 해당 상태의 events 문서로 동작 지정                   |

제품의 **상속**, **원래대로**, **효과 없음**은 위 동작에 맞춰 서로 다른 조작으로 제공한다.

초기 스타일 계약의 속성은 다음을 기준으로 JSON Schema에 고정한다.

| 레이어       | 속성 예                                      |
| ------------ | -------------------------------------------- |
| `background` | color, opacity, image, fit, position, blurPx |
| `decoration` | image, opacity, fit, position                |
| `border`     | color, opacity, widthPx, radiusPx, glow      |
| `icon`       | image, sizePx, opacity, fit, paddingPx       |
| `text`       | color, opacity, weight                       |

`color`는 #RRGGBB, 투명도는 별도 숫자 0~1이다. `image`는 패키지 안의 `assets/` 경로다. `fit`은 cover, contain, stretch, tile 중 해당 레이어가 지원하는 값이다. 크기는 유한한 제한 범위의 숫자로만 표현한다.

`position`은 x/y 비율로 표현하며 원시 CSS 문자열을 받지 않는다. 흐림·빛 등의 세부 구조와 범위는 Effect Registry 및 대응 JSON Schema에 고정한다. 이 표만으로 임의 속성이나 CSS 함수를 허용하지 않는다.

원본 배경을 투명하게 할 때는 어댑터가 해당 배경 속성만 제어한다. 텍스트·아이콘·보조 버튼까지 투명해지거나 숨겨져서는 안 된다.

## 6. 효과 계약

| 필드            | 의미                                                           |
| --------------- | -------------------------------------------------------------- |
| `id`            | 상태의 이벤트 목록 안에서 고유한 효과 인스턴스 ID              |
| `layer`         | background, decoration, border, icon, text 중 지원 대상        |
| `effect`        | 레지스트리에 등록한 효과 ID                                    |
| `effectVersion` | 효과 해석 계약의 정수 버전                                     |
| `durationMs`    | 0~10,000ms                                                     |
| `delayMs`       | 0~5,000ms                                                      |
| `easing`        | linear, ease-in, ease-out, ease-in-out 또는 검증한 곡선 데이터 |
| `iterations`    | 정수 1~100 또는 조건부 infinite                                |
| `reverse`       | 프리셋의 진행 방향 반전 여부                                   |
| `parameters`    | 효과별 JSON Schema를 통과한 매개변수                           |

events는 `enter`, `exit`, `click`, `idle`을 지원한다. infinite는 명시적으로 선택한 idle 효과에만 허용한다. repeat 간격·고급 곡선 등은 레지스트리 계약에 필드를 추가해 정의하며, 임의의 문자열을 실행 코드로 해석하지 않는다.

효과를 둘 이상 넣을 때 delay와 duration으로 순차·동시 재생을 정한다. 같은 레이어의 같은 속성이 시간상 겹치면 validation 오류로 표시한다. 검증된 조합 프리셋은 내부 장식 레이어를 분리해 충돌을 해결할 수 있다.

퇴장은 마지막 상태의 exit를 사용한다. 선택된 채팅 위에서 마우스가 나갈 때는 선택 스타일로 돌아가야 한다. 새 상태와 공유하는 배경을 무조건 0으로 만들지 않고, 현재 시각 상태에서 새 최종 외형으로 전환한다. 빠른 상태 변경 시 이전 실행을 취소하고 이어 간다.

지원 능력 ID 예:

- `target:sidebar.thread-row`
- `target:navigation.search`
- `effect:reveal.edge@1`

실제로 사용하는 대상·효과는 manifest의 required 또는 optional에 한 번씩 선언한다. 필수 항목이 빠지거나 선언하지 않은 기능을 사용하면 패키지 오류다. 선택 기능이 미지원이면 해당 규칙·효과를 생략하고 누락 목록을 미리보기에 표시한다. 효과가 생략돼도 지원하는 정적 스타일은 유지한다.

OS 동작 줄이기와 전체 효과 끄기는 패키지 설정보다 우선한다. 정적인 색·이미지·선택 표시는 유지한다. 움직이는 이미지의 정지 처리도 이 정책을 따른다.

## 7. 이미지와 경로

v1 이미지 후보는 PNG, JPEG, WebP, GIF, AVIF다. 실제 디코더 지원과 크기를 검사한 형식만 가져온다. 움직이는 이미지 형식은 정지 프레임 생성까지 검증되어야 지원으로 표시한다. SVG·동영상·사용자 스크립트·원격 URL은 v1 패키지에서 허용하지 않는다.

자산은 패키지에 포함하고, 외부 절대 경로나 HTTP 요청 없이 해석한다. 이미지 변환이 필요하면 공유 패키지 원본은 보존하고 로컬 파생 자산을 만든다.

경로 규칙:

- 루트 파일은 `manifest.json`, `theme.json`; 그 밖의 파일은 `assets/` 또는 `preview/` 아래.
- 내부 경로 문자는 소문자 ASCII 영문·숫자·하이픈·밑줄·점과 구분자 /만 허용.
- 절대 경로, 드라이브 문자, 역슬래시, 빈 경로 조각, . 또는 .. 조각, 심볼릭 링크는 거절.
- Windows 예약 파일명과 끝의 점, 같은 경로 중복, 대소문자 정규화 후 충돌은 거절.
- ZIP의 실제 항목과 manifest 파일 목록이 정확히 일치해야 함. 디렉터리 항목은 내용 파일로 세지 않음.
- 자산 참조는 선언된 실제 파일에만 연결하고 MIME 표기뿐 아니라 파일 바이트와 디코딩 결과를 확인.

## 8. 자원 제한 초안

| 항목                  | 초안 상한                            |
| --------------------- | ------------------------------------ |
| 압축된 패키지         | 100MiB                               |
| 전체 압축 해제 데이터 | 250MiB                               |
| 파일 개수             | manifest 포함 512개                  |
| 각 JSON 문서          | 2MiB, 중첩 깊이 32                   |
| 프로필·규칙           | 프로필 32개, 프로필당 규칙 256개     |
| 상태당 효과           | 전체 이벤트 합계 32개                |
| 이미지 파일           | 개별 25MiB                           |
| 이미지 해상도         | 개별 32메가픽셀, 한 변 16,384px 이하 |

크기 정보는 ZIP 헤더만 신뢰하지 않고 실제 읽는 바이트 수도 제한한다. 이미지 디코딩은 별도 시간·메모리 예산을 두며 애니메이션 프레임 수까지 검증한다. 위 상한은 제품 성능 검증 후 조정할 정책값이다.

과도한 파일을 일부만 잘라서 성공으로 표시하지 않는다. 이유를 알려 주고 원래 보관함과 적용 상태를 유지한다.

## 9. 가져오기 처리 순서

1. 선택한 파일을 CoSkin 임시 작업 공간으로 복사하고 컨테이너·크기 확인.
2. 항목 목록 검사 후 제한된 스트리밍 읽기로 manifest와 theme 파싱.
3. JSON 중복 키, 필수 필드, 타입, 범위, ID 중복, 경로를 검사.
4. 모든 파일의 크기·해시·이미지 디코딩·참조 관계를 검사.
5. 형식 버전과 CoSkin 최소 버전, 대상·효과의 지원 능력을 검사.
6. 테마 정보·미리보기·생략될 선택 기능을 표시.
7. 같은 ID·버전의 기존 테마와 비교하여 중복, 새 버전, 내용 충돌을 구분.
8. 사용자가 가져오기를 완료하면 설정·자산을 내부 저장소에 복사하고 테마스킨 목록에 원자적으로 등록.
9. 목록에 새 스킨을 표시. 이후 목록에서 선택·적용할 때 내부 ID·리비전으로 제품 설계서의 적용 트랜잭션 수행.

등록 이후 외부 원본 `.coskin` 파일과의 연결은 필수가 아니다. 원본 파일을 이동·삭제해도 목록의 스킨을 계속 적용할 수 있어야 한다. 기본 제공·직접 만든 스킨은 `.coskin` 파일을 거치지 않고 내부 목록에 저장된다.

필수 기능이 미지원인 패키지는 이유를 표시하고 설치·적용하지 않는다. 사용자가 내려받은 원본 파일은 수정하거나 삭제하지 않는다. 실패 시 CoSkin이 생성한 임시 데이터만 정리한다.

파일 더블클릭은 이 가져오기 흐름의 진입점이다. Codex 연결이 아직 준비되지 않았으면 대기 중인 가져오기 요청을 보존한다. 정상 작업 중인 Codex를 강제로 재시작하거나 즉시 테마를 적용하지 않는다.

## 10. 내보내기 처리 순서

1. 저장된 테마 리비전 또는 사용자가 선택한 편집 초안을 확정.
2. 내보낼 프로필을 정하고 필요하면 현재 적용 범위의 외형을 평탄화.
3. 참조된 자산만 수집하고 개인 PC의 절대 경로를 내부 상대 경로로 변환.
4. 합성 화면으로 미리보기 생성 또는 사용자가 지정한 미리보기 확인.
5. JSON·이미지 바이트 확정 후 파일 크기와 SHA-256 작성.
6. manifest를 생성하고 동일한 가져오기 검증으로 패키지 검사.
7. 임시 출력 파일을 완성한 뒤 사용자가 선택한 `.coskin` 경로에 저장.

같은 콘텐츠는 정규화된 JSON과 안정된 경로 순서를 사용한다. ZIP 시간 정보처럼 바뀔 수 있는 값은 고정하여 재현 가능한 출력을 목표로 한다. 최종 검사는 구성 문서·자산과 적용 결과를 비교하며 ZIP 파일명만 비교하지 않는다.

## 11. 버전과 이행

`formatVersion`은 컨테이너·문서 계약, manifest의 `version`은 테마 콘텐츠, `engine.minVersion`은 엔진, `effectVersion`은 효과의 의미를 나타낸다. Codex 버전 호환성은 CoSkin 어댑터에서 별도로 판단한다.

지원하지 않는 formatVersion은 추측해서 열지 않는다. 향후 이행은 원본 파일을 보존하고 새 로컬 사본에서 수행한다. 알려지지 않은 임의 필드는 v1에서 거절한다. 기능을 추가할 때는 형식·효과 버전과 capabilities를 함께 검토한다.

표준 형식 1을 확정하기 전에는 이 문서와 예제를 함께 수정할 수 있다. 공개 릴리스 이후에는 같은 버전의 의미를 소급 변경하지 않는다.

## 12. 구현 전 고정할 세부 계약

다음은 구현 P1~P2에서 JSON Schema와 Effect Registry로 기계적으로 고정한다.

- 스타일 필드별 정확한 숫자 범위, 기본값과 null 처리.
- 프리셋별 입력·제어 속성·허용 레이어와 기능 ID.
- 고급 곡선 데이터 구조와 반복 간격의 필드.
- 지원 이미지별 정지 프레임 추출·디코딩 한도.
- 공통 검사 코드의 오류 코드와 한국어 메시지.

현재 단계의 산출물은 설계 계약과 유효한 예제 데이터다. 이 문서를 완성된 스키마 구현이나 모든 효과의 지원 증거로 취급하지 않는다.

## 구현 교정: 이미지와 로컬 설정

PNG (`image/png`, `.png`), JPEG (`image/jpeg`, `.jpg` 또는 `.jpeg`), GIF (`image/gif`, `.gif`)를 확장자·바이트 형식·실제 디코딩으로 검증한다. 개별 이미지 최대25MiB, 패키지 최대100MiB, 총 압축 해제 최대250MiB의 현재 안전 한도와 GIF 디코딩 한도를 각각 적용한다. 내부 적용은 패키지 원본 경로가 아니라 내부 해시 자산과 불변 리비전을 사용한다.

이미지 레이어의 `imagePlayback: "play" | "poster"`는 움직이는 이미지 재생/정적 대표 프레임을 선택한다. UI 전환의 `motion.mode: "none"`과 별개다. 같은 이미지의 해시는 MIME·원본 바이트와 함께 보존하며 이미지 불투명도는 레이어에만 적용한다.

앱 UI 언어·앱별 움직임 정책·현재 Codex 프로젝트/채팅 안정 ID의 개별 예외는 PC 로컬 설정이다. `.coskin`의 공유 데이터에 실제 채팅 제목·프로젝트 경로·현재 화면 캡처를 자동 포함하지 않는다. 개별 예외를 전체 규칙으로 명시 이동하면 해당 generic 규칙은 공유 테마에 포함할 수 있다.


### 결과물·소스 패널 대상

`summary.surface`는 Codex 소유 결과물·소스 패널의 안정적인 `data-summary-panel-variant=summary` 표면을 지정한다. 배경 레이어의 불투명도는 패널 배경에만 적용되며 원래 글자와 아이콘의 불투명도에는 적용하지 않는다. 기존 테마의 규칙을 자동 추가하거나 변경하지 않는다. 이 대상을 포함한 테마는 요구 기능에 `target:summary.surface`를 선언한다.
