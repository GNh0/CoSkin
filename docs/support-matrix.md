# CoSkin 지원·검증 범위

## 0.1.15 새로고침과 보조 패널 배경

트레이 새로고침은 창별로 처리하고 숨김·스크롤·편집 상태에서는 기존 화면을 보존한 채 갱신을 예약합니다. 화면 활성화나 이동을 요구하지 않습니다. 종료된 창은 건너뛰고 응답 지연은 창별 2초로 제한합니다.

오른쪽·하단 패널의 바깥 구조는 배경 적용 대상으로 탐색하며, 패널 바탕에는 가독성을 위한 반투명 색을 유지합니다. 컴퓨터 영상, 브라우저 문서, 편집기 본문, 메시지 카드와 팝업은 독립적으로 보호합니다. 현재 실제 작업창의 바탕 및 숨겨진 보조 창이 있는 새로고침을 확인했으며, 미지의 모든 레이아웃이나 실제 5~10개 동시 영상 재생을 검증한 것은 아닙니다.

## 0.1.14 깊은 화면 구조와 화면 이동 없는 등록

2026-10-03. 현재 Dot의 실제 DOM에서 공통 main 아래 여러 전체 크기 래퍼와 불투명한 messaging/thread 표면을 확인했다. 단일 전체 크기 분기를 최대16단계까지 검사하고, 뒤늦게 붙는 일반 구조물도 재탐색한다. 실제 오른쪽 패널 표식과 cloud computer 영역은 원래 배경을 유지한다. 관측한 Dot 구조·메시지와 컴퓨터 패널 보호·늦은 구조물 추가를 자동 회귀로 검사했으며, 변경 후 실제 Dot의 모든 상태를 시각 검증했다는 뜻은 아니다.

실제 승인된 새 테마1개를 `showLibrary: false` 공식 가져오기 경로로 등록했다. 현재 페이지 위치·main 요소·입력 포커스·목록 닫힘 상태를 유지하고 기존 라이브러리 항목·리비전·설정 바이트와 원래 Codex 프로세스·창 ID를 보존했다. 기존 대화형 가져오기 기본 동작은 유지한다. Node280개·호스트489개·ESLint·TypeScript 검사가 통과했다.5개나10개 영상을 동시에 재생하는 부하 검증을 추가한 변경은 아니다.

## 0.1.12 다중 창과 관리 화면 검증

2026-10-03. 한 resident의 연결 한도와 동시에 움직임을 재생하는 한도를 분리했다. 기본값은5연결/2재생이며 설정 범위는1~10이다. 닫히거나 지연되는 화면의 재시도, 응답 전달, 초기화 준비와 공유 전송 장애를 분리한다. 편집·미리보기·미완료 요청은 연결 해제 전에 다시 검사한다. 초기화 응답을 확인하는 동안 다음 요청이 끝나면 같은 제한된 전달 작업에서 그 응답도 처리하도록 회귀 재현 후 수정했다.

실제 지원 대상2창에 연결하고, 보이는1창의 기존 영상에서20초601프레임·손실0을 관측했다. 기본5/2 설정의 저장과 복원을 확인했으나, 이는5개 또는10개 영상을 동시에 재생한 부하 검증이 아니다. 기존 Codex 주 프로세스와 원래 창 ID, 설정 바이트·라이브러리·리비전을 보존했다. 이전 간헐 .NET 오류 대화상자는 재현되지 않았으므로 그 원인을 확정하지 않는다.

배경만 보기에서 실제 상단 메뉴와 가로 배치 버튼이 유지되고 아래 화면이 가려졌다. 기존 플레이어를 재사용한 대표 화면을 캡처하고 재토글 뒤 입력 포커스·스크롤·플레이어가 복원됨을 확인했다. Windows 기본 창 제어는 변경하지 않는다. 실제 상단 구조를 찾지 못하거나 공간이 부족하면 CoSkin 메뉴와 단축키로 제공한다.

기존 두 영상 테마로 실제 폴더/트리의 미리보기·한 줄 목록, 상세 첫/마지막 테마 및 되돌아가기7상태를 검사했다. 가로 넘침0, 관리 페이지 video 요소0, 한 줄 목록의 미리보기 이미지와 미디어 조회 배지0을 확인했다. 카드의 `동영상 · 0:21`/`0:17` 및 상세의 길이는 실제 컨테이너 값과 일치했다. 미리보기 읽기 중에도 이전·다음 버튼이 동작하며 실제 적용 바인딩과 배경 플레이어는 유지됐다. 저장·편집과 미확인 요청은 계속 보호한다.

새 채팅과 프로젝트 시작 안내를 기본 숨김으로 제공하고 다시 표시 설정을 보존한다. 공통 shell/semantic main과 큰 구조물에 대한 새 화면 검사는 자동 회귀로 확인했다. Dot의 모든 상태나 아직 나오지 않은 임의 화면까지 지원을 보장하지 않으며, 메시지·작은 기능 패널·컴퓨터 미리보기·에디터·내장 콘텐츠는 원래 그리기를 유지한다.

Node274개·호스트481개·ESLint·TypeScript 검사를 통과했고 최종 Windows x64 portable을 빌드했다. 개인 미디어·대화·원시 검수 파일은 공개 배포에 포함하지 않는다.

## 0.1.9 연결·WebM 검증

2026-10-02. 일반 원본 Codex 연결을 인증된 명명 파이프로 바꾸어 Node inspector WebSocket 경로를 제거했다. 별도 Node24.13.1 프로세스에서는 쪼개진 큰 inspector 프레임으로 접근 위반 종료를 재현했다. 사용자가 보고한 실제 Codex(Node24.19.0)의 이전 종료 예외는 확보하지 못했으므로 동일 원인으로 단정하지 않는다.

수동 Export WebM 약2.85MB와 큰 WebM 약262MB를 실제 기존 Codex 프로세스에서 각각30초 재생했다. 두 영상의 측정 구간은 각각1812/1821프레임, 손실0이었다. 큰 영상은 최소화10초 동안 재생 위치가 유지되고 복원 뒤 진행했다. 같은 Codex 프로세스와 라이브러리·리비전·설정637개 파일을 유지했다. 이 검수는 모든 코덱·장시간·PC 환경의 안정성 보증이 아니다.

영상은 음소거 네이티브 video 요소로 재생하며 매 프레임 캔버스로 복사하지 않는다. 큰 바이트 응답을 평가할 JS 코드 문자열에 넣지 않고 함수 인수로 전달하며, 파이프 전송·Blob과 목록용 PNG 캐시를 사용한다. 현재 Codex CSP를 완화하지 않으며 로컬HTTP 직접 미디어 경로를 실제로 사용했다고 주장하지 않는다. 프로세스 전체 메모리는 Codex 대화·탭 등의 비용도 포함하므로 CoSkin 단독 메모리 비용과 구별한다.

신규 영상 등록의 디코딩 검사도 CSP를 확인하며, HTTP가 차단된 현재 Codex에서는 재생과 같은 파이프·Blob 경로를 쓴다. 별도25초60fps/30fps 동일 구도를 각각30초 재생해1819/911프레임·손실0을 확인했다.30fps 파일은약31% 작았으며 해당 실행 GPU3D 중앙값은3.42%/1.86%였다. 기존 Codex 작업을 포함하는 단일 실행 결과로서 모든 환경의 절감률은 아니다.

관리 화면9가지 상태에서 가로 넘침이 없고 한 줄 목록의 미리보기 요소가0개임을 확인했다. 실제 폴더 선택창은 열기·취소를 검사했다. 최종 설치는635리비전·라이브러리·설정637파일과 원본 미디어1328파일을 SHA256으로 보존했다. Node242·호스트367·보관 폴더80·PNG 캐시25검사와 정적 검사·Windows x64 빌드가 통과했다. 실제 Explorer 재시작은 사용자 세션을 방해하지 않고 상태 기계의 실패/회복 검사로 대체했다.

## 0.1.6 연결 변경

2026-10-01. 원본 Codex **26.928.2636.0 / 내부 앱 26.928.21956**에 재시작 없이 연결하고 기존 테마와 배경 영상 재생을 확인했다. 원본 실행 파일과 chrome.dll의 유효한 OpenAI 서명, Windows 패키지 계열·경로, 실제 x64 연결 export 계약, nonce·PID·포트 정체성과 지원 문서를 검사한다. 버전 번호·ASAR·chrome.dll의 고정 허용 목록은 사용하지 않는다. 화면 어댑터는 실제 DOM 마커를 탐색한다.

동일 연결 계약을 유지한 새 버전은 별도 허용 목록 갱신 없이 검사·연결한다. 아직 나오지 않은 V8 ABI나 화면 구조 변경까지 동작을 보장하지는 않는다. 기능이 바뀌면 데이터를 보존하고 대기하며 CoSkin 수정이 필요할 수 있다. 조회·관리 변경의 검증은 [0.1.6 릴리스 안내](release-0.1.6.md)를 참고한다.

## 0.1.3 당시 연결 대상

0.1.3 당시 일반 바로가기로 실행한 원본의 네이티브 연결은 Windows 패키지 **26.924.2738.0**, 내부 앱 **26.924.22138**에서 검증했다. 이때 사용한 정확한 버전·ASAR·chrome.dll 해시 허용 목록은 0.1.6에서 기능 검사로 교체했다.

기존 패키지 26.924.1866.0 / 내부 26.924.20706의 전용 관리 연결 경로는 호환 코드로 유지한다. 이 구버전의 일반 실행 독립 연결을 검증한 것은 아니다.

두 앱의 권한 수준이 같아야 한다. 보통은 둘 다 일반 권한으로 실행한다. 관리자 권한 Codex에 일반 권한 CoSkin을 연결하는 경로는 지원하지 않는다. CoSkin을 실행해도 Codex 파일·ASAR·원래 바로가기를 변경하거나 Codex를 강제 종료하지 않는다.

0.1.3 당시 디버깅 통로는127.0.0.1의 임시 포트였다. 0.1.9 일반 원본 연결은 인증된 명명 파이프를 사용하고 서버 PID·시작 시각을 검증한다. 현재 구조와 소유권 해제는 [실행 구조](resident-architecture.md)에 설명한다.

## 성능 결과의 해석

행 위 포인터 변경은 해당 장식만 갱신한다. 휠 스크롤 처리에서 전체 문서 재탐색과 행 위치 계산을 제거했다. 움직이는 왼쪽 목록의 GIF·효과는 스크롤 동안 잠시 쉬고, 고정 배경 GIF는 계속 재생한다. 화면 밖·최소화·움직임 줄이기는 별도 정책으로 처리한다.

실제 검수용 Codex에서 GIF 배경을 재생하고 스크롤 처리 함수를 40ms 간격으로 24번 호출했을 때 프레임 인덱스가 진행했고 재생 중지 플래그는 꺼져 있었다. 해당 함수 처리 시간의 P95는 약 0.1ms였다. **이것은 합성 스크롤 처리 검사이며 실제 마우스 휠의 전체 프레임률·GPU·CPU 벤치마크가 아니다.** 고해상도 GIF 여러 개와 모든 효과 조합의 자원 비용은 남아 있다.

Windows 움직임 줄이기가 켜져 있으면 기본 정책에서 GIF가 정지할 수 있다. 효과 설정에서 움직임 허용을 선택한 검사에서는 재생을 확인했다. README의 이미지와 GIF는 기능 예시이며 모든 환경에서 매끄러운 스크롤을 보증하지 않는다.

0.1.2는 최소화와 명시적인 재생 해제를 분리한다. 실제 MP4는 최소화한 위치에서 복원 후 계속 진행했고 동일한 플레이어가 유지됐다. GIF의 남은 프레임 지연과 반복 횟수는 실제 Controller·Decoration·MediaPlayer를 결합한 시계 검사로 확인한다. 움직이는 글자색을 매 프레임 계산하지 않으며, 대표 프레임의 팔레트는 미디어별로 한 번 계산한다.

0.1.3은 보조 창 초기화 지연을 주 창 연결 실패로 오인하던 재시도 경계를 분리했다. CoSkin 배경 오버레이는 Codex 표면의 실제 모서리 값을 사용하고, 움직이는 앱 배경은 GIF와 MP4 모두 상단 기본 제어 영역 아래에서 시작한다. 실제 설치본에서 오른쪽 아래 검은 모서리 잔여 영역이 사라지고, GIF 프레임 진행 및 기존 적용 테마 유지가 확인됐다.

밝은 치카 영상과64% 어두운 본문 배경에서는 실제 적용 글자색 `#f2efef`와 합성 밝기 범위를 확인했다. 가장 밝은 프레임을 흰색으로 가정한 계산 대비는 약4.66:1이다. 이 값은 실제 화면 전체의 모든 글자 픽셀을 측정한 결과는 아니다.

밝은 영상 위의 Windows 메뉴와 대화 제목줄은 테마 바탕색을 96% 불투명도로 합성해 대비를 안정시킨다. 실제 두 상단 영역에 색이 적용됨을 확인했고, 밝은·어두운 바탕에 대한 글자색 계산과 영역 제거 시 원래 스타일 복원을 검사했다. 영상 배경은 1080p를 권장하며, 4K 영상은 디코더·영상 크기와 사용 중인 미디어 예산에 따라 제한될 수 있다.

## 배포 자료

ZIP에는 CoSkin.Loader.exe, renderer.js, THIRD-PARTY-NOTICES.txt만 포함한다. CRC·원본 파일 일치·SHA-256·manifest 게시자 서명을 확인한다. 네이티브 연결 DLL과 공개 업데이트 키는 실행 파일에 포함한다. 실행 파일의 Windows Authenticode 서명과 업데이트 manifest 서명은 서로 다르며, 이 배포는 Authenticode 서명된 실행 파일이라고 안내하지 않는다.

설치 UI는 Windows 네이티브 그리기 검수에서 네 언어의 카드·토글·아이콘과 문구를 확인했다. Windows 화면 캡처 도구의 오류로 최종 설치 화면의 전체 키보드 동선을 직접 검증했다고 주장하지 않는다.
