# CoSkin 아키텍처와 변경 절차

## 언어와 책임

호스트는 .NET 10 LTS의 C#을 사용한다. Windows 패키지·서명·프로세스/창 검증, 제한된 로컬 연결, ZIP/파일 경계, hash 자산과 불변 리비전 저장, 적용 단계와 복구를 담당한다. 최종 이용자에게 Node를 요구하지 않는다.

렌더러는 Chromium에서 실행되는 ES 모듈이다. 상태·범위 합성 및 선언형 효과 계약의 의미 검증은 strict TypeScript `src/core`에 있다. 개발시 esbuild가 실제 모듈 그래프를 묶는다. 설치된 검증 대상 Codex에 이 번들을 연결해 검증 함수를 호출하므로 호스트가 동일한 테마 의미 규칙을 C#으로 다시 구현하지 않는다. C#의 ZIP/이미지 byte/파일 경계 검사는 신뢰 경계의 별도 책임이다. 렌더러 전체의 strict 타입 전환은 아직 진행 중이다.

현재 저장 계약은 JSON 객체와 hash 참조이다. `ThemeDocument`는 manifest/theme/assets와 로컬 개별항목 override를 담고, assets 값은 내부 SHA-256이다. 교환 package는 자산 경로에 원본 bytes를 담는다. 개별 채팅·프로젝트 ID는 로컬 override에만 두며 공유 테마에 포함하지 않는다. UI 언어는 테마 데이터에 저장하지 않는다.

## 모듈 경계

- `src/core`: 테마/manifest 계약, 상태·범위 합성, 효과 registry, 명시적 UI 상태, GIF 타임라인과 제한.
- `src/renderer/adapter.js`: 지원 Codex 버전의 실제 stable data 속성, 대상/문맥 탐색, rail 진입과 전용 shell 페이지의 보존·복원.
- `gallery`, `detail`, `editor-context`, `effects-editor`, `components`, `page.css`: 화면과 구조화된 설정. 미리보기는 실제 채팅 DOM을 캡처하지 않는 합성 레이아웃이다.
- `locale`, `messages`, `label-messages`, `control-messages`, `panel-messages`, `error-messages`: 앱 html lang 우선과 번역. 중국어 지역값은 간체, 미지원 언어는 영어 fallback이다.
- `controller`, `layers`, `media`, `gif-worker`: 변경 push, 필요한 대상 갱신, 원래 입력 노드 보존, 독립 레이어, 미디어 디코딩/재생/해제.
- `src/CoSkin.Loader`: Windows 시작/신원, 창 가시성, 로컬 연결, 라이브러리, package 및 오류 경계. 복구 실패 원문은 진단에 남기고 사용자에게 분류 메시지를 전달한다.

## 저장·적용

저장은 새 리비전을 만든다. 적용은 별도 scope→테마/리비전/프로필 연결을 바꾼다. 각 연결된 창을 준비시키고 적용한 뒤 파일을 원자 교체한다. 실패하면 이전 summary로 복원한다. import는 ZIP·bytes·의미 검증과 ID 충돌을 검사한 뒤 내부 자산을 저장한다. create/save/apply 역시 hash 파일 존재와 무결성·MIME경로를 검사한다. 다중 창 연결 중단/복구와 모든 저장 실패의 독립 검수는 추가로 필요하다.

제품 파일 입력·다운로드는 24KiB 조각 전송을 사용하며 전체 package base64 왕복을 제거했다. 저장소 테스트 호환 경로에는 base64 입력이 남아 있다. 호스트의 ZIP 처리·전송 소비와 브라우저 다운로드는 전체 byte 배열을 아직 사용하므로 최대 패키지의 스트리밍·순간 메모리는 후속 최적화 및 실측 대상이다. 분할 전송만으로 최저 메모리 달성을 주장하지 않는다.

## 자원과 수명

정적 유휴 상태에서는 전체 목록·문서·대상 탐색을 반복하지 않는다. MutationObserver는 자체 노드 변경을 제외하고, pointer/focus는 필요한 대상만 갱신한다. 연결 건강 확인은 가벼운 주기 작업이며 실제 성능은 독립 프로세스 측정으로 판단한다.

동일 hash 디코드 요청은 Promise로 공유한다. GIF 프레임은 공유하고 렌더링 canvas는 표시 크기에 제한한다. 단일 scheduler가 활성 재생만 처리하고 유한 GIF는 원본 반복 메타데이터를 존중한다. 완료/숨김/움직임 줄이기/폐기 시 timer·WAAPI·bitmap·worker·observer를 정리한다. 디코드 캐시는 128MiB/64개 이하, 사용되지 않는 LRU는 8MiB 이하로 유지한다. 순간 디코드 피크·원본 bytes·호스트 메모리는 별도 실측 대상이다.

검증 PID의 HWND 후보를 실제 renderer rect와 비교해 정확히 한 개일 때 연결한다. 최소화/비표시/cloaked/모니터 밖을 검사한다. 불명확한 HWND는 움직임만 중지하고 정적 편집은 유지한다. 동일 위치 여러 창·혼합 DPI·다른 창에 완전히 가려짐은 아직 지원 완료로 표시하지 않는다.

## 재현과 변경

정확 버전 package-lock, Node 24 LTS, .NET 10 LTS를 사용한다. `node scripts/bundle.mjs`, `npm test`, `npx tsc --noEmit`, `dotnet build`, host console tests가 재현 명령이다. PowerShell 실행 정책을 변경하지 않는다. 번들 모듈 ID와 C# PathMap은 저장소 상대이며 Release에는 PDB를 배포하지 않는다. gifuct-js 및 js-binary-schema-parser MIT 원문은 `THIRD-PARTY-NOTICES.txt`로 배포한다.

Codex 새 버전은 새 stable 속성 관찰→어댑터/지원 버전 변경→계약 경계 tests→실제 원래 조작/접근성/복원/가상화 검사→메모리·CPU 실측→지원표 갱신 순서로 추가한다. hash 검사를 무력화하거나 원본 ASAR/실행 파일을 수정하지 않는다.

현재 결과의 기준은 [구현 상태](support-matrix.md)이다. `docs/review`의 독립 검수와 실제 이미지/GIF는 검수 담당자가 작성하며 제품 코드가 성공을 대체하지 않는다.

## 현재 Windows 배포 경계

검증된 `--port` 복사본 연결과 `--prepare-launch`의 공식 설치 발견·서명/hash 확인·재사용을 일반 사용자 설치 완료로 해석하지 않는다. 원본 Codex가 실행 중이면 일반 실행 가드를 유지하며 원본을 종료하거나 두 번째 인스턴스를 임의 실행하지 않는다. self-contained 초기 publish는 생성했으나 최신 전체 기능을 포함한 최종 산출물 검수는 남아 있다.

`WindowsInstaller`의 설치/제거 명령, 저장소별 단일 인스턴스 채널, 파일 가져오기 전달, 사용자 범위 등록 및 전용 시작 메뉴 바로가기, 실패 복구는 소스로 연결되어 있다. 실제 사용자 설치/제거 및 실행 중 제거 잔여 정리는 검수 대기다. 사용자 보관함과 자산을 삭제하지 않는다.

### 실행 연동과 시스템 트레이

`Codex + CoSkin` 전용 바로가기의 `--with-codex` 명령이 실행 옵션을 읽는다. 원래 Codex 바로가기와 원본 설치 파일은 변경하지 않는다. CoSkin 직접 종료는 Codex를 종료하지 않으며, 검증한 관리 복사본의 실행 기록과 포트 소유권·서명·원본 해시를 확인하여 재연결한다. 종료 연동은 검증한 대상 프로세스의 종료 이벤트를 사용하고 핸들을 즉시 반환한다. 실제 여러 창/프로세스와 Explorer 재시작 검수는 남아 있다.

`NativeTray`의 전용 메시지 스레드가 아이콘·네이티브 메뉴를 소유한다. 비동기 명령은 별도 작업으로 전달하며 메뉴 스레드를 막지 않는다. 적용은 기존 다중 창 준비/복구 계약을 사용하고 편집·미리보기·진행 중 명령을 보호한다. 실행 설정은 테마와 독립된 `RuntimePreferenceStore`에 보존한다. 앱 언어를 전달받으며 사용자용 오류는 4언어 중앙 사전으로 표시한다.

### CoSkin 업데이트의 신뢰 경계

공개 배포 신뢰키는 아직 미설정이다. `UpdateService`는 키가 없으면 네트워크나 다운로드를 시작하지 않는다. 검사에 생성한 일회성 키를 배포 신뢰키로 사용하지 않는다. 릴리스 준비 시 별도 보관한 P-256 게시자 키로 정규 서명 manifest를 생성하고 공개키를 제품에 고정해야 한다. 키 회전과 실제 릴리스 검증은 배포 게이트다.

`GitHubUpdateFeed`는 HTTPS·443과 지정 GitHub 다운로드 호스트, 최대 4회 리디렉션, 8KiB 안내 및 200MiB 배포 제한을 유지한다. 서명된 manifest의 저장소·정규 안정 버전·길이·SHA256을 검증하며, 자동 확인은 12시간 간격과 ETag, 실패 지수 백오프를 사용한다. 자동 확인을 끄면 백그라운드 네트워크가 없다. 임시 파일을 스트림으로 검증하고 `UpdateStaging`은 정확한 배포 파일 3개만 해제한다. 현재 호스트 교체의 협조 종료·준비 확인·실패 복구 및 사용자 진행 화면은 통합 중이다.

설치 기록은 안정 버전과 배포 해시로 파일을 구분한다. 설치 트랜잭션 성공 후 현재/직전 정상 버전을 보존하고 더 오래된 **기록된 소유 파일 중 해시가 같은 파일만** 정리한다. 변경되거나 잠긴 파일은 보존하며, 정리 실패는 성공한 설치를 되돌리지 않는다.

## 사용자 효과

`custom-effects.ts`는 수치 키프레임 검증/컴파일의 단일 계약이다. 호스트는 크기·JSON 중복키 경계를 검사하고 등록·저장·import 시 같은 렌더러 검증을 호출한다. 사용자 효과 저장소와 테마 내장 정의를 분리하므로 저장소 삭제가 기존 테마를 변경하지 않는다. 정의 제한, offset 반전, 오류 위치 및 4언어 개발 방법은 [사용자 효과 문서](custom-effects.md)에 기록했다. 7n 실제 파일 입력·실행·왕복 검수는 진행 중이다.
